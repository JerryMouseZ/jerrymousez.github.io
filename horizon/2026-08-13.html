Tailscale 发现 SQLite 16 年 WAL 重置旧 bug ⭐️ 8.0/10

Tailscale 在调查其控制平面数据库损坏问题时，发现了一个存在 16 年之久的 SQLite WAL 重置 bug。该 bug 源于 SQLite 在特定并发条件下重置 WAL 文件时的竞态条件，尽管 Tailscale 采用单写者设计，仍触发了此问题。Tailscale 资助开发了一个开源的 SQLite VFS shim 工具，该工具几乎立即帮助隔离了竞态条件，并可用于未来类似问题的排查。SQLite 官方也提供了详细的 bug 解释。此事件凸显了开源调试工具的价值以及深入理解数据库内部机制的重要性。

hackernews · ropbear · 8月12日 14:22 · 社区讨论

「背景」 SQLite 是一种广泛使用的嵌入式数据库，支持预写日志（WAL）模式以提高并发读写性能。在 WAL 模式下，多个数据库连接可以同时打开同一个数据库文件，但 Tailscale 的设计是单个 Go 进程独占访问数据库，这通常被认为是 SQLite 的推荐用法。然而，Tailscale 在去年遭遇了数据库损坏问题，最终追溯到 SQLite 中一个存在了 16 年之久的 WAL 重置（WAL-reset）竞态条件 bug。该 bug 仅在 WAL 模式激活且同一文件上有多个数据库连接时触发，并且需要读写操作同时发生在同一内存区域。Tailscale 通过资助开发一个开源的 SQLite VFS 垫片（shim）工具，迅速隔离了竞态条件，并帮助定位了根本原因。

「影响」 对于使用 SQLite 并依赖 WAL 模式的开发者，此 bug 可能导致数据库损坏，尤其是在频繁 checkpoint 或并发访问的场景下；Tailscale 资助的 VFS shim 工具为社区提供了新的调试手段，有助于识别和避免类似问题。

「社区讨论」 社区评论普遍赞赏 Tailscale 对开源的支持，认为资助 VFS shim 是公司资助开源工具开发的积极案例。有评论者指出，单写者设计仍可能因 checkpoint 逻辑与写入并发而触发竞态，并好奇 Tailscale 为何选择如此频繁的 checkpoint 策略。也有评论引用 Dijkstra 的话，强调测试无法证明没有 bug，并希望 Tailscale 继续与 SQLite 保持支持合同。

Adam 的逐坐标二阶矩破坏旋转不变性，丢失低秩偏差 ⭐️ 8.0/10

一项新研究指出，Adam 优化器的逐坐标二阶矩破坏了旋转不变性，导致在矩阵感知任务中丢失梯度下降（GD）固有的低秩偏差，而 GD、共享标量 Adam、Muon 和 Shampoo 等优化器则保留该偏差。作者在欠定矩阵感知上测试了九种更新规则，在匹配训练损失下比较，发现 Adam、RMSProp、Lion、signum 和 Adafactor 丢失低秩偏差，而 GD、共享标量 Adam、Muon 和 Shampoo 保留。通过一个单参数族将 Adam 的分母从逐坐标变为共享标量，恢复性能单调提升，表明问题源于各向异性而非自适应性。Muon 在纯低秩目标上表现精确，但随着谱尾能量增加而快速退化，在约 4%尾能量处与 GD 交叉。作者还发现其先前优化器的逐坐标裁剪破坏了结构，改用全局范数裁剪后恢复误差从 0.347 降至 0.220。论文见 arXiv:2608.05136，代码见 GitHub。

reddit · r/MachineLearning · /u/EtherealGlyph · 8月12日 16:39

「背景」 Adam 优化器按坐标维护二阶矩，这使其更新规则依赖于参数空间的坐标基，而标准随机梯度下降（SGD）具有旋转等变性，即对参数进行正交变换不影响其更新。这种旋转敏感性已被先前研究指出，例如有工作专门探讨了 Adam 的旋转依赖假设。本帖子进一步提出，正是这种各向异性（而非自适应性本身）破坏了矩阵感知中隐含的低秩偏好，并通过一个从逐坐标到共享标量的参数族实验加以验证。

「影响」 该发现为优化器选择提供直接指导：在矩阵感知或类似低秩结构任务中，使用 Adam 类逐坐标自适应优化器可能损害隐式正则化，而 GD 或旋转不变优化器更可靠。但需注意，理论仅覆盖无记忆规则，动量部分为经验结果，且部分性能数据（如超光谱数据 43-44%的误差降低）依赖训练集学习率规则，实际差距可能更小。

Chrome 与 Firefox 缩放小 JPEG 的差异解析 ⭐️ 7.0/10

一篇技术文章解释了为何在 Chrome 中显示小尺寸 JPEG 图像时，其外观与 Firefox 不同。原因在于 Chrome 在解码 JPEG 时采用了一种下采样优化，以牺牲部分图像质量为代价提升性能，而 Firefox 则采用不同的缩放算法，通常产生更清晰但可能带有轻微振铃伪影的图像。文章指出，对于图标等小图像，应使用合适分辨率的 PNG 格式，而非 JPEG。Firefox 正在 Bugzilla 中推进相关修复（bug 2033250），以改进低分辨率解码。这一差异对 Web 开发者有实际影响，尤其是在 Electron 应用中，Chrome 的优化曾导致图标显示异常。

hackernews · gutechh · 8月12日 14:00 · 社区讨论

「背景」 浏览器在显示图片时，通常会对过大的图片进行缩小（downscaling）以适配显示尺寸。Chrome 和 Firefox 采用了不同的缩放算法和优化策略，导致同一张图片在两个浏览器中呈现的视觉效果不同。Chrome 的优化可能更注重性能，而 Firefox 则更注重图像质量，这导致了社区对两种浏览器渲染差异的讨论。

「影响」 对于依赖 Chrome 或 Electron 渲染小尺寸 JPEG 或 PNG 图标的 Web 开发者，此差异可能导致图标模糊或出现伪影，需改用合适分辨率的 PNG 或调整缩放策略。
