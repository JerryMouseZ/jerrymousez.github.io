DeepSeek 发布 v4.1-Flash-1017 模型 ⭐️ 8.0/10

DeepSeek 发布了名为 DeepSeek-V4.1-Flash-1017 的新模型，并在 Hugging Face 上提供模型页面，同时通过 DeepSeek API 文档新闻页和 OpenRouter 提供访问入口。据社区评论转述，DeepSeek 官方新闻页显示该版本在多项编程基准上得分明显提升，在 11 项基准中的 10 项超过 Sol 5.6（评论者指出 6.1 才是最新版）。上述基准对比来自厂商自述与社区转述，尚无独立验证；来源本身仅包含链接，未给出具体参数、上下文长度或定价细节。

hackernews · theykk · 10月17日 08:21 · 社区讨论

「背景」 DeepSeek 官方新闻页称，V4.1-Flash-1017 相比上一版本在基准测试上更强、任务完成更快、输出更短，并称这是性能与成本上的帕累托改进，已上线官网、应用和 API。OpenRouter 页面显示其定价为每百万输入 token 0.08 美元、每百万输出 token 0.50 美元，缓存读取为每百万 token 0.008 美元。

「实际影响」 对开发者而言，该模型已可通过 DeepSeek API 和 OpenRouter 调用，社区反馈其吞吐速度和首 token 延迟表现突出，并允许查看思维链。但一位评论者用同一份改动超过 200 个文件的 C++ 游戏引擎代码做对比时，DeepSeek v4.1 Flash 耗时约 20 分钟只找出一处相关 P1 问题和一处不相关的 P2 问题，而 GPT 5.6 Sol 约 5 分 30 秒找出两处相关问题，说明速度优势与缺陷检出效果需按任务分别评估。

「社区讨论」 有评论者认为 DeepSeek 在基准上未必胜过 Sol 和 Gemini，但凭借高吞吐、低首 token 延迟以及可查看思维链、较少被安全审查拦截的开放性，实际使用体验更好。也有评论者称将重新用 DeepSeek 写代码，同时仍用 Opus/Sol 做实现规划和代码审查；另有评论者从生态多样性角度支持此类开放模型。这些均为个人使用体验，不构成对基准结论的独立验证。

iPhone 18 Pro 据称实现重启保留的 untethered 越狱 ⭐️ 8.0/10

一则来自 Telegram 的投稿称，@calif_io 演示了 iPhone 18 Pro 的 untethered 越狱，重启后越狱状态仍保留、无需连接电脑，并称这是自 iOS 9 以来首个公开的完整越狱。该说法称攻击链涉及 cryptex 子系统、TSS 票签欺骗和 PAC 保护绕过三层，并提到 Apple 于 9 月 14 日修补了 273 个漏洞。目前证据仅为这一条社交媒体来源的转述，没有技术细节、受影响系统版本、披露状态或独立验证，因此应视为未经证实的演示声明，而非已确认的能力。

telegram · zaihuapd · 10月17日 10:34

「背景」 越狱通常分为“tethered”（重启后失效、需连接电脑重新引导）和“untethered”（重启后仍保留越狱状态）两类，后者因需绕过启动链与内核的多层防护而更为罕见。据外部报道，Calif.io 是在 Hexacon 2026 会议上现场演示了运行 iOS 27.0.1 的 iPhone 18 Pro 的 untethered 越狱，重启后可通过 SSH 获得完整 root 权限；不过 Apple 虽列出两项与 Calif.io 相关的漏洞发现，并未将其与该演示直接关联。

「潜在影响」 若该演示属实，受影响的是运行当前 iOS 版本的 iPhone 18 Pro 用户：一条可跨重启保留的公开越狱链意味着设备完整性和沙箱边界可能被绕过，而 Apple 在 9 月 14 日发布的更新中修复了 273 个漏洞，说明该攻击链可能依赖尚未修补的问题。由于目前只有单一社交媒体来源、没有技术细节或披露状态，用户和开发者应将其视为未经证实的演示，在 Apple 确认或发布补丁前不宜据此调整安全假设。

hackernews · theanonymousone · 10月17日 03:18 · 社区讨论

「背景」 爱沙尼亚的互联网投票系统 IVXV 并非首次公开源码：学术资料指出，该系统大部分组件的源代码早已可在其 GitHub 仓库中查看，但实际选举中使用的确切代码版本仍保持私有，每次选举所用版本应对应仓库中的某个提交。爱沙尼亚选举机构也长期在官网集中发布自 2017 年选举以来的源码与相关文档。

「社区讨论」 有评论者认为，软件乃至软硬件组合本身都无法确保选举安全，因为存在“信任信任的反思”这类问题以及固件验证需求；可行的做法是在投票结束后尽快通过人工、统计随机抽样的方式验证机器确实正确运行。爱沙尼亚本地评论者则表示，电子投票在当地被广泛接受，其开源在 IT 社区中早已为人所知并受到赞赏，本地专家和国际社区对其有效性并无固有怀疑；但也有人担忧，当前系统依赖对政府的信任，一旦这种信任被侵蚀，数字计票与人工计票的差别可能不再重要。另有评论者提到，ElectionGuard 自 2020 年起已在美国多场真实选举中使用，反驳了“此类系统从未实际使用”的说法。

全球太阳能发电量首次超过核电 ⭐️ 7.0/10

据 pv-magazine 报道，全球太阳能发电量首次超过核电。太阳能装机容量同比增长 27%，增加 510 GW 至 2,383 GW；风电新增 159 GW 至 1,291 GW，增长 14%；核电装机容量仅增加 1.5 GW 至 399.5 GW，在运核电容量还下降了 0.5 GW。评论引述的数据称，2025 年 3 月至 2026 年 6 月期间，太阳能或风能各自每月发电量都超过核电，2026 年 3 月至 5 月两者同时超过核电。上述数字来自报道及评论转述，并非独立核实的一手统计。

hackernews · xbmcuser · 10月17日 14:01 · 社区讨论

「背景」 这一数据来自《世界核工业状况报告》（WNISR）2026 年版，该报告按实际发电量而非装机容量进行跨国比较。太阳能发电量在 2025 年首次超过核电，同期全球太阳能装机容量增至 2,383 GW，而核电装机容量基本持平于略低于 400 GW。

「实际影响」 太阳能发电量领先是在其容量系数明显低于核电的情况下实现的，说明装机规模的快速增长已足以在总发电量上弥补出力波动。对电网运营方而言，这意味着日内发电结构更依赖天气和时段，傍晚光伏出力下降后的供电与电价安排将更受关注。

「社区讨论」 有评论者强调这是实际发电量（太瓦时）的超越，并指出风电也即将超过核电，下一个里程碑是太阳能发电量超过水电，但按当前速度还需数年。另有评论者质疑这类里程碑对普通用户的意义，称分时电价在日落后大幅上涨，太阳能装机再多也难缓解晚间用电成本；也有人惋惜核电停滞，认为本可更接近无化石燃料电网。

OpenCode 遭蒸馏攻击，约 1.4% 用户 API 密钥外泄 ⭐️ 7.0/10

OpenCode 确认，一起大规模蒸馏攻击导致约 1.4% 的 Console 用户所存储的 OpenAI、Anthropic 和 Google API 密钥被暴露，受影响账户已收到邮件通知。公司表示正与这三家厂商协同处置，但目前尚无法确认这些密钥是否已被恶意使用。官方建议受影响用户在对应平台后台吊销并重新签发密钥，检查 10 月 17 日以来的用量，并设置支出上限。

telegram · zaihuapd · 10月17日 23:43

「背景」 OpenCode 是一个供开发者调用第三方大模型 API 的编程工具，用户可在其工作区中保存 OpenAI、Anthropic 等厂商的密钥。此次事件中，这些存储的第三方密钥可能已被泄露，官方因此要求用户前往各厂商后台吊销并更换密钥、更新相关应用，并检查近期用量是否异常。

当写作沦为工作量证明：LLM 如何瓦解职场文本 ⭐️ 7.0/10

rss · Sean Goedecke · 10月18日 00:00

「背景」 科技公司大量依赖写作来充当“证据”：证明流程被遵守、证明投入了努力、证明写作者理解了某个领域。作者借用比特币的工作量证明（proof-of-work）作类比，指出这类文本的价值往往不在内容本身，而在于“你确实坐下来写了它”。

「方案」 作者把写作证据分为三类。第一类是合规证据，如风险评诂、影响评估等强制模板，其目的常是满足法律要求、展示重视或吓退轻率的改动，因此只需草草写出看似合理的内容即可。第二类是努力证据，如咨询公司上百页的报告，真正要传达的只有第一页，其余九十九页只是证明调研扎实、钱没白花；独自做项目时填写的工单也类似，主要价值是证明自己没在摸鱼。第三类是学习证据，典型是大组织层层汇总的状态报告（rollup），写报告迫使管理者建立对自身领域的基本认知，报告存在本身就说明管理者掌握情况。这类证据依赖抽查来防伪，而区块链能自动验证哈希，公司只能事后或抽样核查。作者认为，要击破这种机制，需要能按需生成文本，而 2023 年 LLM 恰好做到了：合规证据更空洞，努力证据被彻底摧毁（一小时、几美元即可生成百页报告），学习证据也失效，因为可以写出从未经过自己头脑的详细报告。作者承认学校、监管机构同样受冲击，并列举了可能的应对：改用视频或现场汇报等更难伪造的证据、禁止 AI 生成特定文本（难以执行）、让 LLM 审查代码判断投入程度，但他认为没有好办法，这种“流程仍在、人人可轻易钻空子”的悬置期可能持续很久。

「启示」 作者的结论是：写作已不再是任何东西的证据，工程师应趁还能利用时利用这套系统，同时避免被他人利用——不必认真阅读 LLM 生成的文档，也不必亲手撰写只为充当证据的文档，把精力留给真正用于沟通的写作。
