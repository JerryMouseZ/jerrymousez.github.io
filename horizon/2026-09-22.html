Cloudflare Python Workers 结束两年预览正式 GA ⭐️ 8.0/10

Cloudflare 宣布其 Workers 平台上的 Python 支持在经历两年预览后正式可用，官方称 Python 现已成为 Cloudflare Developer Platform 上“一等、完全支持的语言”。其实现方式是通过 Pyodide 将 Python 编译为 WebAssembly，运行在基于 V8 的 workerd 运行时中。官方文档列出的限制中，最突出的是 multiprocessing 和 threading 在 WebAssembly 虚拟机中无法工作。本地开发方面，pywrangler 工具（在 PyPI 上以 workers-py 发布）会在本地完整模拟该技术栈，包括在一个 123MB 的 workerd 二进制中于 V8 内以 WebAssembly 执行 Pyodide。

rss · Simon Willison · 9月21日 22:25

「背景」 Cloudflare 的 Python Workers 在预览阶段运行了两年，此前 Python 代码只能以实验性方式部署在 Workers 平台上。该实现并非原生 CPython，而是通过 Pyodide 将 Python 编译为 WebAssembly，再运行在基于 V8 的 workerd 运行时中，因此 multiprocessing 和 threading 在 WebAssembly 虚拟机内无法工作。

「影响」 对希望在边缘运行 Python 的开发者而言，Python 现在可作为受支持的语言使用，但依赖多进程或多线程的代码在 WebAssembly 环境中无法运行，需要改用其他并发方式或避开这些标准库模块。本地开发需引入 pywrangler（PyPI 包名 workers-py）及其约 123MB 的 workerd 二进制，这会增加项目依赖体积。

「社区讨论」 一位 urllib3 维护者指出，urllib3 多年前已合并了添加 Pyodide/Emscripten 支持的大型贡献，后来又加入 JSPI 支持，才使 Requests 得以在此环境工作，并称相关资金给了实现该工作的外部贡献者而非 urllib3 维护者。Wasmer 的 syrusakbary 表示，尽管两家产品存在竞争，Cloudflare 的工作仍令人振奋，并认为自首次发布以来在包支持方面有实质进展，例如 PyEmscripten 已通过 PEP 783 标准化，但他也提到一些架构层面的顾虑仍然存在。另有评论者询问 WebAssembly 方案在冷启动方面的表现。

xAI 发布 Grok 4.7：权重增 40%，价格不变 ⭐️ 7.0/10

xAI 发布了新前沿模型 Grok 4.7。据社区评论，其权重比 Grok 4.6 增加约 40%，而定价保持不变，为每百万输入 token 2 美元、输出 token 6 美元。该发布比原定时间推迟了近两周，且赶在传闻中的 Opus 5.5 发布前一天推出。评论者反映 4.7 明显更慢、更贵，并对其基准测试提升的实际价值存疑。

hackernews · meetpateltech · 9月21日 15:50 · 社区讨论

「背景」 Grok 4.7 是 xAI 在 Grok 4.6 之后推出的新一代前沿模型，据外部报道其基础模型规模更大（约 2.1 万亿参数），并采用更长的强化学习训练，定价维持在每百万输入 token 2 美元、每百万输出 token 6 美元。该模型通过 xAI API、Cursor、Grok Build 及第三方平台提供。

TypeSafe AI 发布 Jev：输出类型化概率决策的 LLM ⭐️ 7.0/10

TypeSafe AI 上周发布 Jev，这是其称为“System One 模型”的新类别模型的第一个实例，输入文本后不返回文本，而是返回对应类别、是/否问题、评分及置信度的浮点数。Jev 按输入 token 计费，输出免费，首个模型输入价格为每百万 token 0.042 美元，低于 OpenAI GPT-5 Nano 的 0.05 美元。API 接受单个“state”文档并支持并行评估多个问题，官方将其定位为“非结构化状态输入，类型化概率决策输出”的前沿智能函数调用。目前该能力来自厂商发布，尚无独立基准验证。

rss · Simon Willison · 9月21日 23:09

「背景」 传统 LLM 以 token 为单位逐字生成文本，输入和输出都按 token 计价，输出通常更贵。TypeSafe AI 称 Jev 属于其新提出的“System One 模型”类别：接收非结构化状态输入，在一次并行推理中直接返回带类型的概率化决策，而非文本。据 TypeSafe AI 博客，Jev 在 System One 任务上的智能水平与现有 LLM 相近，但速度快、效率高约两个数量级，目前处于早期访问阶段。

「影响」 对分类、垃圾邮件检测、标签建议、排序和搜索重排等任务，开发者可以用极低成本批量运行实验；但 Jev 只返回浮点数，不提供决策理由，因此评估和结构化实验比常规 LLM 项目更关键，偏见问题也更难排查。

「社区讨论」 发布后社区已出现多种非常规用法：Kyle Pena 的 jevchat 把 Jev 变成逐符号生成的聊天模型，Fatih Kadir Akın 的 jev-leftpad 用选择查询实现 left-pad，Andy Gayton 的 jev-2048 用它玩 2048。另有基于 Qwen 3.5 的开源复刻项目 Kev（0.8B、4B、9B），并已出现 JevBench 基准用于比较“Jev 级决策模型”。

M6 Mac mini 实测：多核追平 Intel 旗舰，GPU 接近翻倍 ⭐️ 7.0/10

极客湾对苹果新款 M6 Mac mini 的实测显示，其 CPU 采用 2+4+6 核配置、台积电 N2 工艺，超大核频率 4.8 GHz，多核性能与 Intel Panther Lake X9 388H 打平，单核继续领先，较 M4 提升超过 50%。GPU 升级至 12 核，光追与游戏表现大幅增强，游戏性能接近 M4 的两倍。功耗方面，CPU 满载约 25W，双烤整机约 65W。上述数据来自单一评测渠道的实测，尚待更多独立测试验证。

telegram · zaihuapd · 9月21日 16:32

「背景」 M6 是苹果首款用于 Mac 的 2nm 处理器，采用台积电 N2 工艺，也是苹果首款同时使用三种 CPU 核心类型的芯片：2 个超大核、4 个性能核和 6 个能效核。相比 M4 的 3nm 工艺与 10 核（4P+6E）配置，M6 在相同功耗下晶体管密度提升约 10%–15%，超大核频率最高可达 4.8 GHz。

「影响」 对关注小型台式机的用户而言，M6 Mac mini 的实测数据意味着其多核性能已进入 Intel Panther Lake 旗舰 X9 388H 的同一区间，而单核仍保持领先，因此以多核吞吐为主要瓶颈的编译、渲染等本地工作负载不再必须转向 x86 平台。GPU 提升至 12 核、游戏性能接近 M4 两倍，也扩大了该机型在轻度游戏和光追场景的可用范围；但上述结论来自单一实测来源，且未提供与 Panther Lake 平台的同条件对比细节，实际选购仍需等待更多独立复测。
