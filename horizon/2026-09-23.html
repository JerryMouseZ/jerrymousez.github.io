vLLM v0.30.0 发布：新增模型、MXFP8 KV 缓存与快速启动 ⭐️ 8.0/10

vLLM 发布 v0.30.0，包含来自 315 位贡献者的 762 次提交。该版本新增 DeepSeek-V4.1-Flash、GLM-5.3-Flash、K2-Horizon、Cohere Compass 等模型支持，并引入 MXFP8 KV 缓存、FlashMLA/DeepGEMM 内核以及 ROCm、CPU 后端。新增的 Fast Start 通过常驻每 GPU 权重缓存守护进程，将量化并张量并行分片后的权重保留在显存中，重启引擎时以 `--load-format ipc_cache` 经 CUDA IPC 映射，而非从磁盘重新加载。该版本还包含多项破坏性变更，例如 scale-out 端点改为通过 `--enable-scale-out` 显式启用，并移除了 GPTQ 的 `g_idx` 激活排序。

github · khluu · 9月22日 05:20

「背景」 vLLM 是广泛使用的开源大模型推理与服务引擎，其版本迭代通常包含新模型支持、内核优化与后端扩展。上一版本 v0.29 已移除十种废弃的模型架构，并将 FlexOlmo、Olmo3 和 Hunyuan V1/VL 迁移到 Transformers 建模后端，同时弃用 `python -m vllm.entrypoints.openai.api_server` 而改用 `vllm serve`（tool-2-2）。v0.30.0 延续了这一清理方向，进一步移除 GPTQ 的 `g_idx` 激活排序、删除 0.29 已弃用的环境变量，并将 scale-out 端点改为通过 `--enable-scale-out` 显式启用。

「影响」 使用 vLLM 部署服务的团队在升级前需检查破坏性变更：scale-out 端点不再默认开启，需显式传入 `--enable-scale-out`；GPTQ 激活排序（`g_idx`）被移除；0.29 中弃用的 `VLLM_PREFIX_CACHE_RETENTION_INTERVAL` 和 `VLLM_MM_HASHER_ALGORITHM` 环境变量已删除；`python -m vllm.entrypoints.grpc_server` 被弃用，改用 `vllm serve --grpc`。此外，YaRN 行为已与 Transformers 对齐，厂商 YaRN 别名不再重新缩放 `max_model_len`，可能影响依赖该行为的现有配置。

DeepSeek 与清华发布 DSec 沙箱平台技术报告 ⭐️ 8.0/10

DeepSeek-AI 与清华大学联合发布技术报告《DeepSeek Elastic Compute（DSec）》，公开了支撑大规模 Agent 训练与评测的沙箱基础设施。DSec 通过统一 SDK 提供 FnCall、容器、Firecracker microVM 和完整 VM 四种后端，覆盖 OJ 判题、软件工程、安全渗透、电脑操作等负载，并将有状态的 rollout 执行与可抢占的 GPU 训练解耦。报告给出的规模数据为：单个生产单元约 160 个节点，每天服务约 300 万个沙箱实例，峰值并发超 38 万，创建速度超每秒 5000 个，单节点可承载 3200 个容器或 800 个 microVM。平台基于 3FS 分布式文件系统按需加载 EROFS 镜像，相比传统 Docker 全量拉取，任务完成时间快 1.7 倍、磁盘写入减少 57%，内存共享与回收机制使峰值内存占用下降约 40%。

telegram · zaihuapd · 9月22日 04:45

「背景」 智能体训练需要在大量隔离环境中反复执行代码、操作软件和完成评测任务，沙箱的创建速度、并发密度与资源开销直接决定训练吞吐。传统做法通常依赖 Docker 全量拉取镜像，启动慢且磁盘写入量大，难以支撑每天数百万次的环境创建。DSec 报告正是针对这一环节，给出四种隔离后端与镜像按需加载的设计。

「影响」 对从事智能体训练与评测的团队而言，报告披露的 1.7 倍任务完成加速、57% 磁盘写入下降和约 40% 峰值内存下降，说明沙箱层的镜像加载与内存回收优化可以显著降低同等规模训练的基础设施成本。四种后端共用统一 SDK，也意味着不同隔离强度（从 FnCall 到完整 VM）的负载可以在同一套接口下调度，但报告未说明这些后端是否对外部用户开放或开源。

开发者用 Rust/wasm 运行时复活 Visual FoxPro ⭐️ 7.0/10

一位开发者将 2007 年停更于版本 9 的 Visual FoxPro 移植到新的运行时上：该运行时用 Rust 编写并编译为 wasm，并对照真实的 vfp9.exe 进行校验。项目解除了表 2 GB 的大小限制，仍可加载旧的 32 位 .fll 插件，并新增了 lambda、JSON 和 HTTP 服务器支持。项目以 MIT 许可发布，但报告功能尚未完成，构建产物也未签名。

hackernews · boredjohnny · 9月22日 21:00 · 社区讨论

「背景」 Visual FoxPro 是微软的数据库与快速应用开发语言，2007 年在发布 9.0 Service Pack 2 后停止开发，官方支持延续到 2015 年。正因大量基于它的业务应用仍以 32 位形式运行，这次复活项目才选择在 Rust 编译到 wasm 的新运行时上兼容原有语言，并对照真实的 vfp9.exe 进行验证。

「影响」 对仍在维护 20 年前 FoxPro 业务应用的开发者而言，这个运行时提供了一条不重写代码就能继续运行旧程序的路径，但未签名的构建和缺失的报告功能意味着它目前还不适合直接用于生产环境。

「社区讨论」 评论者 mikestew 指出，DBC（数据库容器）设计存在严重安全漏洞：DBC 必须对所有用户可读写且没有权限机制，其存储过程以明文保存在 memo 字段中，可执行任意 FoxPro 代码乃至 Win32 调用，因此可被篡改。另有开发者回忆了 2006 年用 FoxPro 搭建诊所患者跟踪系统时遇到的文件锁和并发修改问题，以及早年用 FoxPro 快速开发 CRUD 应用并获利的经历。
