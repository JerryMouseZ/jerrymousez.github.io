光子发射引导激光故障注入攻破 RP2350 安全调试 ⭐️ 8.0/10

研究人员演示了利用光子发射引导的激光故障注入，绕过 RP2350 微控制器的安全调试保护。该攻击通过定位芯片运行时的光子发射点来精确瞄准注入位置，从而突破安全调试锁定。文章给出了完整的实验方法与实验室细节，但未提供可复现的开源工具或量产级攻击条件。

hackernews · synack · 9月18日 16:54 · 社区讨论

「背景」 树莓派此前为 RP2350 举办过安全破解挑战，官方仓库说明挑战固件会运行安全版本，并刻意关闭可能受故障注入影响的调试输出，目标是提取 OTP 中的密钥。2025 年 1 月公布的挑战结果显示，该破解是历时数月、经过大量失败尝试与反复验证的项目；随后官方又启动了聚焦 RP2350 加密启动侧信道分析的第二轮挑战。

「影响」 该攻击针对的是 RP2350 的 secure debug 保护，而非其 Secure Boot 或 OTP 密钥存储机制；因此将 RP2350 用作 FIDO2 安全密钥（如 Pico Keys 等项目依赖 Secure Boot 与 OTP 来防止密钥被提取或克隆）的开发者，不应把这一结果直接等同于密钥存储已被攻破。评论者 BitBangingBytes 指出，原研究使用了约 25 万美元的实验室设备，但同类攻击可在低于 2.5 万美元、甚至低于 1 万美元的家庭实验室中复现，并以 PicoEMP（约 50 美元）替代 ChipShouter（约 5000 美元）复现 BAM BAM 攻击为例。

「社区讨论」 评论者 BitBangingBytes 认为，虽然原研究使用了约 25 万美元的实验室设备，但家庭实验室用不到 2.5 万美元、甚至不到 1 万美元即可复现，并举例称自己用 50 美元的 PicoEMP 复现了 Colin O&#x27;Flynn 用 5000 美元 ChipShouter 完成的 MPC5566 攻击。byb 指出 RP2350 的安全飞地曾使其成为 YubiKey 替代方案的候选，并认为这类攻防是持续升级的军备竞赛。

一篇技术调查文章指控 ZCode 在用户不知情的情况下将本地 Git 历史上传至云端，引发社区对 AI 编程代理访问本地文件的广泛讨论。据社区评论引用的厂商声明截图，z.ai 已就此事致歉，并解释问题源于 ZCode 的“代码库索引”（codebase indexing）功能，称已立即展开内部审查。目前公开信息主要来自该调查文章与厂商声明，尚无独立验证的细节。

hackernews · csmantle · 9月18日 06:11 · 社区讨论

「背景」 ZCode 是智谱（Z.ai）推出的官方 AI 编程桌面应用，其“代码库索引”功能用于帮助用户检索代码。据调查报道，该应用在用户登录状态下会将整个工作区打包上传至阿里云 OSS，内容包括完整的 .git 历史、LFS 资源缓存、reflog 以及全局应用配置，且界面上的开关无法阻止这一行为。

「影响」 对使用 ZCode 的开发者而言，此次事件表明本地 Git 历史可能在该工具未明确告知的情况下被上传至云端，因此需要检查并调整其“代码库索引”等联网功能的设置，或限制代理对本地仓库的访问范围。评论中提到的沙箱与权限分类器绕过问题也提示，仅依赖自动权限模式不足以阻止代理读取 .gitignore 或点文件等敏感内容。

「社区讨论」 有评论者质疑，在自动模式下依赖模型判断权限本身就不可靠，代理可能绕过沙箱访问磁盘任意内容，沙箱的意义因此存疑。另有开发者称在自建代理框架中观察到 GLM 和 DeepSeek 倾向于读取 dotfiles 与 .gitignore 中列出的文件，并认为应从 Grok Code 事件中吸取教训、不要轻信新的代理框架。

Android 17 被指未向 AOSP 发布新 API ⭐️ 7.0/10

GrapheneOS 在社交平台发帖称，Android 17 是自 Android 3.x 以来首个在未向 AOSP 发布源码的情况下就新增 API 的版本，引发对 Pixel 独占 API 与 Android 开放性的担忧。社区评论进一步解释称，Google 每年向 OEM 和公众发布两次“真正的”Android 源码更新，但每年为 Pixel 推送四次更新（含文档与 SDK），此次新增 API 出现在仅面向 Pixel 的更新中。评论还指出，Google 每月向“受信任”OEM 提供安全更新回移，GrapheneOS 多年来一直能获取这些回移。上述说法来自社交帖子与社区解读，尚无官方文档佐证。

hackernews · theanonymousone · 9月18日 19:03 · 社区讨论

「背景」 Android 的开源模式长期依赖 AOSP：Google 通常将 Android 源代码同步发布给 OEM 和公众，使 GrapheneOS 等第三方项目能够基于同一代码库构建系统。据 GrapheneOS 称，Android 17 QPR1 首次自 Android Honeycomb（3.x）以来在未同步发布 AOSP 的情况下为应用开发者新增 API，这些 API 目前仅存在于 Pixel 系统，其他 Android OEM 无法获取。

「影响」 若该说法成立，依赖 AOSP 源码的 GrapheneOS 等第三方系统将无法获得 Android 17 QPR1 新增的应用开发者 API，只能等待后续 AOSP 发布或自行逆向实现，短期内可能造成功能与兼容性差距。GrapheneOS 还指出，每年第一和第三季度的 Pixel 专属补丁同样不进入 AOSP，这意味着其安全更新节奏可能继续落后于 Pixel 官方版本。

「社区讨论」 有评论者认为 Google 对 GrapheneOS 设置的重重障碍（延迟上游源码补丁、禁运、认证问题等）表明其后悔将 Android 开源；也有人从 BlackBerry 时代的类似经历出发，表示对 Google 作为开源项目托管方几乎零信任。另有评论澄清，问题可能不在于新 API 为 Pixel 独占，而在于每年第一和第三季度的补丁为 Pixel 独占。

Cloudflare 用数学优化再省 100TB 内存 ⭐️ 7.0/10

Cloudflare 发布工程博客，介绍其通过数学方法驱动的优化，在既有基础上又节省了 100TB 内存。文章聚焦于代理与缓存负载均衡场景中的内存占用问题，属于该系列优化的后续进展。由于没有可用的原文内容，具体实现细节、适用版本与部署范围尚无法确认。

hackernews · f311a · 9月18日 18:51 · 社区讨论

「背景」 Cloudflare 此前已通过重新设计 DNS 缓存条目的内存布局，在全球服务器集群中释放了约 100TB 内存，其 1.1.1.1 解析器同时缓存约 2500 亿条 DNS 记录，因此每个条目浪费一个字节就相当于 250GB。本次新文章延续这一优化系列，改用数学方法（并结合 Rust）进一步压缩内存占用。

「影响」 对运行大规模代理或缓存集群的团队而言，这类内存优化直接降低单机内存占用，从而减少节点数量或推迟扩容。社区评论中有人指出，文章未提及专为代理/缓存负载均衡设计的 rendezvous hashing，该算法具有低开销和均匀负载的特性，可能提供另一条实现路径。

「社区讨论」 有评论者（jiggawatts）指出，文章和评论区都未提及 rendezvous hashing，认为它正是为这类代理/缓存负载均衡场景设计的方案。另有评论者（zer0x4d）赞赏 Cloudflare 持续发布此类优化文章，认为内存变贵重新推动了优化实践；也有人（ricardobeat）担忧这类高度优化会让系统变得难以理解。

NHANES 冠心病风险分类项目公开数据泄漏审计与校准检查 ⭐️ 7.0/10

一位 Reddit 用户发布了基于 NHANES 2011-2018 四轮数据、约 21,500 名成年人样本的冠心病分类项目，比较逻辑回归、随机森林与梯度提升，特征涵盖人口学、血压、身体测量和血脂面板。作者发现，若纳入 NHANES 中询问卒中、心脏病发作和心绞痛等其他心血管诊断的问卷变量，PR-AUC 会从 0.23 跃升至 0.51，这主要反映的是自我报告诊断之间的相关性而非真实风险因素，因此他删除了整节变量并公开量化了泄漏幅度。由于冠心病患病率仅约 4%，类别加权逻辑回归的原始概率严重失准（平均预测风险约 30% 对真实 4%），作者在开发集上拟合 sigmoid 重校准并冻结决策阈值后才评估测试集。最终测试集结果为逻辑回归 ROC-AUC 0.875、PR-AUC 0.239，随机森林与梯度提升结果相近，所选阈值下 PPV 仅 0.13。

reddit · r/MachineLearning · /u/YouJonaa · 9月18日 12:36

「背景」 NHANES 是美国国家健康与营养调查，其问卷部分同时包含冠心病结局变量和其他心血管诊断问题，这类高度相关的自我报告变量在预测建模中容易造成数据泄漏。作者在报告中明确区分了开发集与测试集的使用顺序，并指出年龄单独即可达到 0.83 AUC，血压、胆固醇和体型解释了剩余预测能力的大部分。

「影响」 该项目对应用机器学习实践者的直接价值在于量化了泄漏的规模：纳入相关诊断变量会使 PR-AUC 翻倍以上，而这一提升并不代表真实预测能力。作者同时展示了在 4% 患病率下类别加权模型概率严重高估的问题，以及通过开发集 sigmoid 重校准和预先冻结阈值来避免测试集调参的做法。当前特征尚未包含吸烟状况、糖尿病和降压药使用，作者表示这些 NHANES 变量尚未加入。
