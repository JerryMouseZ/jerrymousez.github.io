OpenAI 与 Anthropic 数月内降价最高 80% ⭐️ 7.0/10

一篇分析文章讨论了 OpenAI 和 Anthropic 在数月内将大语言模型价格下调最高 80% 的原因，并引发 Hacker News 上的大量讨论。文章将降价与竞争、推理经济学和监管因素联系起来，但所提供材料未给出具体模型名称、生效日期或官方定价表，因此这些降幅应视为文章的分析结论，而非已核实的厂商公告。

hackernews · minimaxir · 10月25日 21:11 · 社区讨论

「背景」 OpenAI 与 Anthropic 的 API 按 token 计费，推理成本是定价的核心变量；此前 DeepSeek 等厂商以低价模型进入市场，形成了价格参照。据社区评论引用的数据，DeepSeek 声称其 Flash V4 每 GPU 每小时收入 38 美元，按每百万输出 token 0.60 美元、单 GPU 每秒 25,600 个输出 token 计算，扣除部分开销后得出该数字。

「社区讨论」 有评论者称，在遇到 OpenAI 和 Anthropic 的“网络安全”拦截后改用 Kimi 和 GLM 模型，发现访问成本更低且能完成工作。另一位评论者引用 DeepSeek 的说法，称 Flash V4 每 GPU 每小时收入 38 美元，并据此推算大型模型可能仍有降价空间；也有人认为这是不可持续的“逐底竞争”，还有人猜测厂商推动监管是为了保护自身商业模式。这些均为评论者观点或转述，并非独立验证的事实。

10 年前 CNN 在皮肤癌诊断上胜过前沿 LLM ⭐️ 7.0/10

一篇博客文章报告称，一个基于 10 年前 Inception v3 架构、在 ISIC Archive 的 68,011 张皮肤镜与临床图像上全层微调的 CNN，在皮肤癌诊断上优于两个前沿 LLM。作者称测试用的 200 个病灶及同一病灶或患者的其他照片在训练前已从训练集和验证集中移除，且未用于选模型或设阈值。该结果来自单一博客的对比实验，并非同行评审的新研究，其可复现性和外部有效性仍需独立验证。

hackernews · sungam · 10月25日 17:15 · 社区讨论

「背景」 该对比使用在 ImageNet 日常照片上预训练的 Inception v3，在单张 H100 GPU 上以 ISIC Archive 的 68,011 张皮肤镜与临床图像微调全部层，约 20 分钟完成。ISIC Archive 是公开的皮肤影像数据集，此前已有研究用 Inception v3 等预训练网络在 ISIC 数据上做皮肤癌分类，因此这次比较的关键在于把同一类专用模型与通用前沿 LLM 放在同一测试集上对照。

「实际影响」 对医疗 AI 开发者而言，这一对比提示在图像分类这类任务上，小规模专用模型可能比通用 LLM 更合适，LLM 的价值更多在于降低构建和部署专用分类器的成本。不过该结论仅基于一个数据集和 200 个测试病灶，不能直接外推到临床诊断或监管审批场景。

「社区讨论」 评论者普遍认为专用模型胜过通用模型并不意外，有人以 Katago 下围棋和计算器做乘除作类比；Legend2440 则质疑这是“benchmaxxing”，即针对基准调优的模型自然会赢。jonex 提出应关注 LLM 的额外潜力，例如结合病历笔记、主动向患者提问，以及处理纹身等分布外图像。

南北阁发布 Nanbeige4.3-33B：Apache 2.0 小模型智能体教师模型 ⭐️ 7.0/10

南北阁（Nanbeige）发布了 Nanbeige4.3-33B，以 Apache 2.0 许可开放权重，并将其定位为计划中更小智能体（包括一款尚未发布的 3B 模型）的教师模型。模型卡标注 512K 上下文窗口；团队自报在 Terminal-Bench 2.1 上得 80.9 分，高于 Qwen3.8-27B 的 73.0 分，但在 SWE-Bench Pro 上以 60.3 分落后于对方的 61.7 分。上述成绩均为发布方自行评测，尚无独立复现；复现智能体结果时评测保留了先前推理，即 preserve_thinking=true，模型卡建议在多轮工具调用中使用该设置，但不建议用于普通对话。

reddit · r/MachineLearning · /u/jatingargiitk · 10月25日 16:32

「背景」 Nanbeige 此前已发布过面向智能体的小型开源模型，例如采用 Apache 2.0 许可、支持 256K 上下文的 Nanbeige4.2-3B（tool-2-3）。此次 33B 版本是该系列中体量更大的模型，官方将其定位为计划中的更小智能体（包括即将推出的 3B 模型）的教师模型。

「对使用者的影响」 对计划以该模型蒸馏或指导小型 agent 的开发者而言，模型卡建议在多轮工具调用中启用 preserve_thinking=true，而普通对话不建议开启；复现其 agent 评测结果时需保持该设置一致。由于 80.9 对 73.0 的 Terminal-Bench 2.1 成绩和 60.3 对 61.7 的 SWE-Bench Pro 成绩均为发布团队自评、尚无独立复现，且后者落后于 Qwen3.8-27B，选型时应结合任务成功率与总生成 token 数比较，而不宜把榜单分数直接当作部署排名。

Tailscale SSH 转发漏洞可让已控设备获取服务器 root ⭐️ 7.0/10

安全研究者 Erica Windisch 于 10 月 25 日发布针对 Tailscale 与 headscale 的 11 项问题报告「Tailworm」。报告称，在实验环境中，攻击者控制一台获准连接目标的设备，并利用 Tailscale SSH 端口转发，可在目标服务器取得 root 权限；测试并非针对真实网络。截至 10 月 26 日，尚无 CVE 或修复版本。Tailscale 表示正在确认受影响的配置，暂不建议所有用户停用 Tailscale SSH。

telegram · zaihuapd · 10月26日 02:19

「背景」 Tailscale 是基于 WireGuard 的组网工具，其 SSH 功能允许用户按访问规则直接登录网络内设备，而无需管理传统 SSH 密钥；headscale 则是社区维护的自托管控制服务器替代方案。据 The Hacker News 报道，Erica Windisch 在实验室中对 Tailscale 1.104.2 和 headscale 0.29.5 进行了为期三天的测试，并于 10 月 25 日发布包含 11 项问题的「Tailworm」报告，所有发现均在未修改的软件上复现。

「影响与应对」 在修复发布前，管理员应尽量关闭 SSH 端口转发：Tailscale 托管服务可按规则单独设置，而 headscale 0.29.5 无法关闭该功能，因此在该版本上应把每一项 SSH 授权都视为等同于授予目标 root 权限。同时建议收紧访问规则，按单一来源设备与目标设备分别授权，而非放宽到整个网段或用户组。
