Cloudflare 收购 Deno，运行时开发将于一年后终止 ⭐️ 9.0/10

Cloudflare 已收购 Deno。据社区评论引述的公告内容，Cloudflare 将在未来一年内继续支持 Deno 运行时，每月发布包含缺陷修复和安全更新的版本，一年后结束对 Deno 运行时的开发。Deno 仍将保持开源，官方表示欢迎其他人接手继续开发；若无人接手，Deno 将不再获得支持。

hackernews · ilreb · 10月9日 13:03 · 社区讨论

「背景」 Deno 由 Node.js 创始人 Ryan Dahl 创建，长期被视为 Node.js 的替代运行时。据 The New Stack 报道，Deno 团队此前开发了 Celld——一个自托管的 Cloudflare Workers 模式实现，Simon Willison 的博客指出其首个版本于 2026 年 8 月发布。Stork.AI 的分析认为，此次交易实质是 Cloudflare 吸收 Deno 团队，而非直接收购运行时本身。

「影响」 Deno 运行时将在一年维护期结束后停止开发，依赖它的开发者需要在此期间评估迁移或自行接手维护。据社区评论引述的公告，Cloudflare 将提供一年的月度 bug 修复与安全更新，之后 Deno 仍保持开源但不再由官方开发。外部报道指出，Cloudflare 收购的重点是 Deno 团队及其 CellD 技术，用于简化 workerd 上 Workers 与 Durable Objects 的自托管，而非继续维护 Deno 运行时。

「社区讨论」 有评论者认为更准确的标题应是“Cloudflare 通过收购式招聘实际上关闭了 Deno 开发”。多位用户表达惋惜，其中一人称 Deno 是自己最喜欢的 JS 运行时，并希望 workerd 能采纳 Deno 的安全机制以成为更好的沙箱；另一人则表示，自 Deno 将 npm 兼容性列为优先事项后便预感到这一结局，认为其从简洁变得臃肿，并提到早期 Deno 的设计影响了 Node。也有评论将此事列入近期开发者工具领域的一系列收购之中。

Telegram Desktop 7.2.9 以下版本存在任意文件窃取漏洞 ⭐️ 8.0/10

Telegram Desktop 7.2.9 以下版本存在一个严重漏洞（CVE-2026-107181）：用户点击恶意 tg:// 链接后，系统文件可在无确认的情况下被悄悄窃取。漏洞根因是链接中的分号未被转义、被当作独立 IPC 命令处理，配合 interpret: 处理器可读取文档、浏览器会话、SSH 密钥、加密钱包等任意文件。官方已在 7.2.9 版本中修复，建议用户尽快升级、警惕异常 tg:// 链接并启用本地密码。

telegram · zaihuapd · 10月9日 09:51

「背景」 该漏洞被编号为 CVE-2026-107181，CVSS 4.0 评分为 8.6，属于高危级别。其根因是 Telegram Desktop 的 Core::Sandbox 组件存在 IPC 记录分隔符注入问题：恶意 tg:// 链接中未转义的分号可注入 OPEN: 记录，并借由 interpret: 协议处理器把本地文件上传至攻击者频道，包括 tdata 会话密钥，进而可能导致账号被接管。公开的概念验证（PoC）文章已经出现，但该漏洞未被列入 CISA KEV，目前也没有已知的在野利用记录。

「影响」 使用 7.2.9 以下版本 Telegram Desktop 的用户在点击恶意 tg:// 链接时可能被静默读取本地任意文件，因此应尽快升级到 7.2.9 或更高版本，并对来源不明的 tg:// 链接保持警惕。

密码学家 Matthew Green 警告公钥加密信心风险 ⭐️ 7.0/10

密码学家 Matthew Green 在 Twitter 上提出一个最坏情况假设：他认为有 1% 的概率我们生活在 Minicrypt 中——即公钥加密在计算上不可能的世界，另有 15% 的概率我们会从功能上对现有公钥加密算法失去信心。他指出，AI 产生意外发现的速度与人类替换标准的速度相差数个数量级，因此只有提前做好准备，才能从这类意外中恢复。Simon Willison 在引用中补充说明，Minicrypt 是 Russell Impagliazzo 提出的假想世界。

rss · Simon Willison · 10月9日 15:02

「背景」 Minicrypt 是密码学家 Russell Impagliazzo 提出的一个假想计算世界，在其中公钥加密在原理上不可能实现。Matthew Green 的警告正是基于这一概念：他给出的 1% 概率指我们可能身处 Minicrypt，而 15% 概率指我们可能在实际层面失去对现有公钥加密算法的信心。Green 同时澄清，“失去公钥加密”并不意味着加密本身变得不可能，也不等于我们真的生活在 Minicrypt 中。

「影响」 这一警告针对的是依赖现有公钥加密的系统和标准制定流程：Green 认为，即便有 AI 辅助，标准替换的速度也远慢于 AI 带来意外发现的速度，因此相关组织需要提前准备，而非在意外发生后才被动响应。

Talus：23M 参数扩散模型生成游戏地形，可在浏览器 WebGPU 运行 ⭐️ 7.0/10

一位爱好者从零训练了 23M 参数的扩散模型 Talus，用于生成 64x64 的游戏地形高度图（对应 4 公里范围、最高 1,200 米），并以地形类型及五个可测属性（平均海拔、起伏度、平均坡度、水体占比、频谱斜率）的任意子集为条件。模型在单张 RTX 5060（8 GB）上训练约 4.5 小时，数据为自研程序化生成器产出的 45,000 张地图；架构为像素空间 U-Net，采用 v-prediction、余弦调度、50 步 DDIM 与 2.0 的 classifier-free guidance。评估将各项距离除以真实地图两半之间的“真实对真实”噪声下限，当前 TEST 上 W1 为下限的 1.51 倍、频谱 9.1 倍、坡度 1.65 倍；模型已通过 ONNX Runtime Web 在 WebGPU 上运行，单张约 3 秒，并提供 CPU 回退。代码、权重与评分卡以 Apache-2.0 发布。

reddit · r/MachineLearning · /u/Old_Cow_6636 · 10月9日 19:52

「背景」 程序化地形通常依赖 fBm/ridged 噪声与侵蚀模拟，而扩散模型此前多用于图像生成，将其用于可控地形高度图需要解决条件控制与评估基准问题。作者用自研生成器（fBm/ridged 噪声、河流功率侵蚀、坡面扩散、热侵蚀）造出 45,000 张训练地图，并引入“真实对真实”噪声下限作为评估参照，使各项距离指标可解释为相对可区分度。

「影响」 对游戏开发者而言，该模型可在浏览器内通过 WebGPU 生成地形，无需服务端 GPU，且 ONNX 导出与 JavaScript 采样器重实现（与 PyTorch 偏差在 0.6 米内）降低了部署门槛。作者也指出当前局限：山脊与最细频谱带仍未达标，山脉偏平滑、平原偏颗粒感，因此生成结果更适合作为原型或辅助素材，而非直接替代手工或传统程序化管线。

软件工程的半人马时代或持续数十年 ⭐️ 5.0/10

rss · Sean Goedecke · 10月10日 00:00

「背景」 2022 年以来，人类工程师与 AI 编程系统配对工作的“半人马”模式，被认为比任何一方单独工作都更高效。作者 Sean Goedecke 指出，每当 AI 进步，总有人宣称半人马时代已经结束、AI 独霸时代来临，但国际象棋的半人马时代持续了约二十年，更早的织袜业半人马时代甚至长达两百年。

「方案」 作者梳理了这段历史：2022 年 GitHub Copilot 以自动补全起步，随后 GPT-4 带来对话式协助，2024 年 Cursor 的“agent 模式”和 2025 年初的 Claude Code 让编码智能体登场；早期智能体需密切监督，而 2025 年 11 月 Claude Opus 4.5 发布后，作者认为它们已可靠到可完全无人监督运行，其错误更多是“对齐”问题——不符合组织技术价值观、过度或不足工程化、资源分配失当——而非普通 bug。他据此判断：无辅助的工程师已无法战胜半人马团队，但无人监督的智能体也尚未能战胜半人马团队，人类仍在顶端。至于半人马时代会否比国际象棋更短，作者列出六种相互矛盾的理由（软件更难但资金更多、软件总量增长可能反而增加人类工作量、通用 AI 的溢出效应、织袜业先例、技术加速等），最终承认“我们其实不知道会怎样”，但以国际象棋作为最近先例，默认软件半人马时代长度与之相近是合理的。由此他给出职业建议：不要辞职转行；主动拥抱人机协作，拒绝成为半人马注定失败；持续思考人类还能提供什么价值——2023 年是技术专长，如今他个人认为是“对齐”，也有人主张是难以定义的“品味”；不要恐慌性地跳到最坏假设，应关注当下工作如何运作，而非二十年后 AI 彻底改变格局时的样子。

「启示」 作者的核心论点是：软件工程的半人马时代可能持续数十年，足以让工程师规划甚至走完整个职业生涯，因此不应过早恐慌性退出。这一判断建立在类比而非实证之上，作者本人也承认结局难以预料，其价值更多在于为从业者提供一个审慎乐观的思考框架。
